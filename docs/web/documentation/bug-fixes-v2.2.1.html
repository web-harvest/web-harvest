#39

Unified CLI and GUI Settings

Problem: Configuration duplication - GUI used webharvest.properties, CLI required all arguments explicitly.

Solution: Unified settings system with Apache Commons CLI

  • ✅ Single configuration source for both CLI and GUI
  • ✅ Modern -option value syntax
  • ✅ CLI arguments override file settings
  • ✅ Auto-discovery from standard locations

Example:

# ~/.webharvest/webharvest.properties workdir=/projects/scraping proxyhost=proxy.company.com # CLI automatically loads settings java -jar webharvest-cli.jar -c scraper.xml # Override when needed java -jar webharvest-cli.jar -c scraper.xml -w /tmp

Tests: 18/18 passing ✅

#36

HTTP Redirect Header Preservation

Problem: After successful login, HTTP 302 redirect logs user out because headers (Referer, auth tokens) are lost.

Solution: Configurable HttpService with header preservation interceptor

  • ✅ Control redirect following (enable/disable)
  • ✅ Preserve specified headers across redirects
  • ✅ Fixes login workflows
  • ✅ Supports API authentication

Java API:

// Preserve headers across redirects Map<String, String> headers = new HashMap<>(); headers.put("Referer", "https://example.com/login"); headers.put("X-API-Key", "secret"); HttpService service = new HttpServiceImpl(true, headers); // Disable redirects HttpService service = new HttpServiceImpl(false);

Tests: 14/14 passing ✅

#19

Memory Leak in Loop/While (CRITICAL)

Problem: OutOfMemoryError with 4000+ loop iterations, even with 2GB heap!

  • Variables created in loop body never cleaned up
  • Memory grows linearly: 4000 iterations × 3MB = 12GB → OOM crash
  • User had to wrap everything in <empty> as workaround

Solution: Automatic cleanup via nested context

  • ✅ LoopPlugin fixed - each iteration in nested context
  • ✅ WhilePlugin fixed - each iteration in nested context
  • ✅ 4000x memory reduction - constant 3MB instead of 12GB growth
  • ✅ No code changes required - existing configs automatically benefit

Impact:

Before: 4000 items × 3MB/item = 12GB → OOM at iteration 600 After: Constant 3MB (cleanup each iteration) → ✅ 10,000+ items OK

Tests: 4/4 passing ✅ + all existing Loop/While tests

#6

Function Global Variable Access (Already Works)

User Request: "It would be better, if in the function one can refer to global variables, not just the function parameters"

Verification: Functions ALREADY access global variables!

  • ✅ Template expansion in calling context
  • ✅ Can use ${globalVar} in function body
  • ✅ No need to pass everything as parameters
  • ✅ Mix global + parameters freely

Example:

<def var="apiHost">https://api.example.com</def> <def var="apiKey">secret</def> <function name="apiGet"> <return> <http url="${apiHost}/<call-param name='endpoint'/>"> <http-header name="X-API-Key" value="${apiKey}"/> </http> </return> </function> <call name="apiGet"> <call-param name="endpoint">users</call-param> </call>

Tests: 4/4 passing ✅

Proof: docs/web/examples/functions.xml uses global variables

#14

DOM Structure Validation (Already Implemented)

User Request: "There needs to be a way to check for this required structure - walking the DOM and checking if all required nodes are available"

Verification: WebHarvest provides complete DOM validation!

  • ✅ XPath count() - check if nodes exist
  • ✅ XPath boolean() - test conditions
  • ✅ If/Else - conditional execution based on validation
  • ✅ Script - complex multi-condition validation
  • ✅ Try/Catch - graceful handling of missing elements

Example:

<!-- Validate DOM structure --> <def var="hasPrice"> <xpath expression="count(//span[@class='price']) > 0">${page}</xpath> </def> <if condition="${hasPrice}"> <!-- ✅ Structure OK - extract data --> <def var="price"> <xpath expression="//span[@class='price']/text()">${page}</xpath> </def> </if> <else> <log message="Required DOM structure not found"/> </else>

Tests: 6/6 pattern examples passing ✅
