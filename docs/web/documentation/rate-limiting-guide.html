⏱️ Rate Limiting & Scraping Speed Control

Complete guide to responsible web scraping without overloading servers

Home » Documentation » Rate Limiting Guide

📖 The Problem

"I would be very helpful, if the scraping speed (Hitcount) on a webpage could be configurable. As a minimum the web-harvest should support max connections/second to avoid any break down of a webserver/page. Currently webharvest downloads the info with maximum possible connection count per second."
— GitHub Issue #5

Why Rate Limiting Matters

  • 🚫 Avoid server overload - Prevent website crashes
  • 🤝 Respectful scraping - Be a good web citizen
  • 🛡️ Prevent IP bans - Avoid getting blocked
  • ⚖️ Honor robots.txt - Follow crawl-delay directives
  • 📜 Legal compliance - Respect Terms of Service
⚠️ Important: Uncontrolled high-speed scraping can:
  • Crash small websites
  • Get your IP permanently banned
  • Violate Terms of Service
  • Result in legal action
⏰ PATTERN 1: Fixed Delay Between Requests

Simple Time-Based Rate Limiting

The easiest approach: wait a fixed time between each HTTP request.

<!-- Scrape 100 pages with 2-second delay between requests --> <loop item="url" maxloops="100"> <xpath expression="//a/@href">${page}</xpath> <!-- Fetch page --> <http url="${url}"/> <!-- ⏱️ Wait 2 seconds before next request --> <sleep milliseconds="2000"/> </loop>
✅ Result: Maximum 30 requests/minute (1 request every 2 seconds)

Common Delay Values

Delay Milliseconds Requests/Minute Use Case
100ms 100 600 Very light load (small sites)
500ms 500 120 Light load
1 second 1000 60 Moderate load (recommended)
2 seconds 2000 30 Conservative (safe for most sites)
5 seconds 5000 12 Very conservative
10 seconds 10000 6 Extremely polite (fragile sites)
💡 Recommendation: Start with 2-second delays for unknown sites, then adjust based on server response.
📊 PATTERN 2: Configurable Max Connections/Second

Precise Rate Control

Calculate exact delay to achieve desired requests-per-second rate:

<!-- Configuration: 10 requests/minute = 6 seconds per request --> <def var="maxRequestsPerMinute">10</def> <def var="delayMs"> <script><![CDATA[ var rpm = parseInt("${maxRequestsPerMinute}"); var delaySeconds = 60.0 / rpm; Math.floor(delaySeconds * 1000); // Convert to milliseconds ]]></script> </def> <loop item="url"> ${urlList} <http url="${url}"/> <!-- Dynamic delay based on configuration --> <sleep milliseconds="${delayMs}"/> <log message="Rate: ${maxRequestsPerMinute} req/min, delay: ${delayMs}ms"/> </loop>
✅ Result: Exact rate limiting with configurable speed

📈 PATTERN 3: Exponential Backoff (Retry Strategy)

Adaptive Rate Limiting on Errors

Automatically slow down when encountering errors (429, 503, timeouts):

<loop item="url"> ${urlList} <def var="retryCount">0</def> <def var="success">false</def> <while condition="${!success and retryCount < 5}"> <try> <body> <http url="${url}"/> <def var="success">true</def> </body> <catch> <!-- Calculate exponential backoff: 1s, 2s, 4s, 8s, 16s --> <def var="backoffDelay"> <script><![CDATA[ Math.pow(2, parseInt("${retryCount}")) * 1000 ]]></script> </def> <log level="WARN" message="Request failed, retry ${retryCount}, waiting ${backoffDelay}ms"/> <sleep milliseconds="${backoffDelay}"/> <def var="retryCount"> <script>parseInt("${retryCount}") + 1</script> </def> </catch> </try> </while> <!-- Normal delay between successful requests --> <sleep milliseconds="2000"/> </loop>
✅ Result: Automatically slows down on errors, maintains normal speed on success
🎯 PATTERN 4: Respect robots.txt Crawl-Delay

Honor Server Preferences

Read and respect the crawl-delay directive from robots.txt:

<!-- Fetch robots.txt --> <def var="robotsTxt"> <http url="https://example.com/robots.txt"/> </def> <!-- Extract Crawl-delay (in seconds) --> <def var="crawlDelaySeconds"> <regexp> <regexp-pattern>Crawl-delay:\s*(\d+)</regexp-pattern> <regexp-source>${robotsTxt}</regexp-source> <regexp-result> <template>\1</template> </regexp-result> </regexp> </def> <!-- Convert to milliseconds, default to 2 seconds if not specified --> <def var="crawlDelayMs"> <script><![CDATA[ var delay = "${crawlDelaySeconds}"; if (delay && delay.trim() !== "") { parseInt(delay) * 1000; } else { 2000; // Default 2 seconds } ]]></script> </def> <log message="Using crawl-delay from robots.txt: ${crawlDelayMs}ms"/> <!-- Scrape with robot-specified delay --> <loop item="url"> ${urlList} <http url="${url}"/> <sleep milliseconds="${crawlDelayMs}"/> </loop>
✅ Result: Respects server's requested delay, falls back to safe default
⚡ PATTERN 5: Adaptive Rate Limiting (Advanced)

Adjust Speed Based on Server Response

Monitor response times and adjust scraping speed dynamically:

<!-- Configuration --> <def var="baseDelay">1000</def> <!-- 1 second baseline --> <def var="slowThreshold">3000</def> <!-- Response > 3s = slow --> <loop item="url"> ${urlList} <!-- Measure request time --> <def var="startTime"> <script>new Date().getTime()</script> </def> <http url="${url}"/> <def var="endTime"> <script>new Date().getTime()</script> </def> <def var="responseTime"> <script>parseInt("${endTime}") - parseInt("${startTime}")</script> </def> <!-- Adaptive delay: if server is slow, wait longer --> <def var="adaptiveDelay"> <script><![CDATA[ var respTime = parseInt("${responseTime}"); var threshold = parseInt("${slowThreshold}"); var base = parseInt("${baseDelay}"); if (respTime > threshold) { // Server is slow, wait 2x longer base * 2; } else { // Server is fast, use normal delay base; } ]]></script> </def> <log message="Response: ${responseTime}ms, next delay: ${adaptiveDelay}ms"/> <sleep milliseconds="${adaptiveDelay}"/> </loop>
✅ Result: Automatically slows down for overloaded servers, maintains speed for healthy ones
🔄 PATTERN 6: Batch Processing with Pauses

Process in Bursts

Scrape in batches with longer pauses between batches:

<!-- Configuration --> <def var="batchSize">10</def> <def var="batchDelay">30000</def> <!-- 30 seconds between batches --> <def var="requestDelay">500</def> <!-- 500ms within batch --> <def var="totalProcessed">0</def> <loop item="url"> ${urlList} <http url="${url}"/> <def var="totalProcessed"> <script>parseInt("${totalProcessed}") + 1</script> </def> <!-- Check if batch complete --> <def var="batchComplete"> <script>parseInt("${totalProcessed}") % parseInt("${batchSize}") === 0</script> </def> <if condition="${batchComplete}"> <log message="Batch complete (${totalProcessed}), pausing for ${batchDelay}ms"/> <sleep milliseconds="${batchDelay}"/> </if> <else> <sleep milliseconds="${requestDelay}"/> </else> </loop>
✅ Result:
  • Fast processing: 10 requests in 5 seconds
  • Long pause: 30 seconds
  • Repeat cycle
  • Average rate: ~17 requests/minute

⚙️ Complete Configurable Solution

Ready-to-use configuration with all rate limiting options:

<?xml version="1.0" encoding="UTF-8"?> <config> <!-- =================== RATE LIMITING CONFIGURATION =================== --> <!-- Basic Settings --> <def var="MAX_REQUESTS_PER_MINUTE">30</def> <def var="MIN_DELAY_MS">1000</def> <def var="MAX_DELAY_MS">10000</def> <!-- Adaptive Settings --> <def var="SLOW_RESPONSE_THRESHOLD_MS">3000</def> <def var="ENABLE_ADAPTIVE">true</def> <!-- Retry Settings --> <def var="MAX_RETRIES">5</def> <def var="ENABLE_EXPONENTIAL_BACKOFF">true</def> <!-- Calculate base delay --> <def var="baseDelayMs"> <script><![CDATA[ var rpm = parseInt("${MAX_REQUESTS_PER_MINUTE}"); var delaySeconds = 60.0 / rpm; var delayMs = Math.floor(delaySeconds * 1000); // Clamp to min/max var min = parseInt("${MIN_DELAY_MS}"); var max = parseInt("${MAX_DELAY_MS}"); Math.max(min, Math.min(max, delayMs)); ]]></script> </def> <log message="Rate limiting initialized: ${MAX_REQUESTS_PER_MINUTE} req/min, delay: ${baseDelayMs}ms"/> <!-- =================== ACTUAL SCRAPING WITH RATE LIMITING =================== --> <loop item="url"> ${urlList} <def var="retryCount">0</def> <def var="success">false</def> <def var="currentDelay">${baseDelayMs}</def> <while condition="${!success and retryCount < MAX_RETRIES}"> <try> <body> <!-- Measure response time --> <def var="startTime"> <script>new Date().getTime()</script> </def> <http url="${url}"/> <def var="endTime"> <script>new Date().getTime()</script> </def> <def var="responseTime"> <script>parseInt("${endTime}") - parseInt("${startTime}")</script> </def> <!-- Adaptive delay calculation --> <if condition="${ENABLE_ADAPTIVE}"> <def var="currentDelay"> <script><![CDATA[ var respTime = parseInt("${responseTime}"); var threshold = parseInt("${SLOW_RESPONSE_THRESHOLD_MS}"); var base = parseInt("${baseDelayMs}"); if (respTime > threshold) { Math.min(parseInt("${MAX_DELAY_MS}"), base * 2); } else { base; } ]]></script> </def> </if> <def var="success">true</def> <log message="✓ ${url} (${responseTime}ms, next delay: ${currentDelay}ms)"/> </body> <catch> <!-- Exponential backoff on error --> <if condition="${ENABLE_EXPONENTIAL_BACKOFF}"> <def var="backoffDelay"> <script><![CDATA[ var base = parseInt("${baseDelayMs}"); var retry = parseInt("${retryCount}"); Math.min( parseInt("${MAX_DELAY_MS}"), Math.pow(2, retry) * base ); ]]></script> </def> <def var="currentDelay">${backoffDelay}</def> </if> <log level="WARN" message="✗ ${url} failed, retry ${retryCount}, waiting ${currentDelay}ms"/> <def var="retryCount"> <script>parseInt("${retryCount}") + 1</script> </def> </catch> </try> <!-- Wait before next attempt --> <sleep milliseconds="${currentDelay}"/> </while> </loop> </config>
✅ Features:
  • Configurable max requests/minute
  • Min/max delay clamping
  • Adaptive speed based on response times
  • Exponential backoff on errors
  • Detailed logging
  • All settings in one place

📋 Best Practices

✅ DO:

  • Start conservative: 2-3 second delays for unknown sites
  • Read robots.txt: Honor crawl-delay directives
  • Monitor response times: Slow down if server struggles
  • Use User-Agent: Identify yourself properly
  • Handle errors gracefully: Exponential backoff on failures
  • Test with small samples: Before large-scale scraping
  • Scrape during off-peak hours: Less load on servers

❌ DON'T:

  • Never scrape at maximum speed: Always add delays
  • Don't ignore 429/503 errors: Server is telling you to slow down
  • Don't scrape login-protected content: Without permission
  • Don't ignore Terms of Service: Read and follow them
  • Don't use multiple IPs to bypass limits: That's evasion
