<function>

Function definition processor

Core v2.2.0

Overview

The processor defines named, reusable functions that can be called multiple times from different parts of the configuration using . Functions support parameters, local variables, and return values, enabling modular and maintainable scraper configurations.

Usage Examples

Example 1: Simple function

example-1.xml 
<function name="getCurrentDate">
  ${_date}
</function>

<def var="timestamp">
  <call name="getCurrentDate"/>
</def>

Example 2: Function with parameters

example-2.xml 
<function name="fetchProduct">
  <def var="productId"><call-param name="productId"/></def>
  
  <http url="https://api.example.com/product/${productId}"/>
</function>

<!-- Call with different IDs -->
<def var="product1"><call name="fetchProduct"><call-param name="productId">123</call-param></call></def>
<def var="product2"><call name="fetchProduct"><call-param name="productId">456</call-param></call></def>

Example 3: Reusable extraction logic

example-3.xml 
<function name="extractProductInfo">
  <def var="html"><call-param name="html"/></def>
  
  <def var="name">
    <xpath expression="//h1[@class='title']/text()">
      <html-to-xml>${html}</html-to-xml>
    </xpath>
  </def>
  
  <def var="price">
    <xpath expression="//span[@class='price']/text()">
      <html-to-xml>${html}</html-to-xml>
    </xpath>
  </def>
  
  <template>${name}|${price}</template>
</function>

<loop item="url">
  <tokenize>${urls}</tokenize>
  
  <def var="page"><http url="${url}"/></def>
  <def var="info">
    <call name="extractProductInfo">
      <call-param name="html">${page}</call-param>
    </call>
  </def>
</loop>

Important Notes

  • Define before use:: Functions must be defined before calling
  • Parameters:: Retrieved via inside function body
  • Return value:: Last expression in function body is returned
  • Variable scope:: Function has local scope for variables

⚠️ Best Practices & Known Issues (v2.2.0)

Bug #7 Fix: Function Parameter Scope Pollution

Problem (v2.1 - v2.2.0):

Function parameters could "leak" between function calls. If you omitted a parameter in the second call, it would still have the value from the first call!

Example of the bug:

<function name="greet">
    <return><template>Hello ${name}!</template></return>
</function>

<!-- First call WITH name -->
<call name="greet">
    <call-param name="name">Alice</call-param>
</call>
<!-- Result: "Hello Alice!" ✓ -->

<!-- Second call WITHOUT name -->
<call name="greet">
    <!-- Oops! Forgot to pass name -->
</call>
<!-- v2.0: "Hello !" (empty) -->
<!-- v2.1-2.2.0: "Hello Alice!" (from first call!) ❌ -->
<!-- v2.2.0: "Hello !" + WARNING in log ✅ -->

Solution (v2.2.0):

  • Automatic Fix: Bindings cleared before each function call
  • Detection: Warns when scope pollution detected
  • Strict Mode: Optional exception throwing

✅ Best Practice - Always provide ALL parameters:

<!-- GOOD: Explicit empty parameter -->
<call name="greet">
    <call-param name="name"></call-param>  <!-- Empty value -->
</call>

<!-- BETTER: Check if parameter exists -->
<function name="greet">
    <return>
        <case>
            <if condition="${name != void}">
                <template>Hello ${name}!</template>
            </if>
            <else>
                <template>Hello Guest!</template>
            </else>
        </case>
    </return>
</function>

Strict Mode (Testing/Debugging):

# Enable strict mode to catch scope issues early
java -Dwebharvest.script.scope.strict=true -jar webharvest-cli.jar config.xml

# Default (lenient) - warnings in log only
java -jar webharvest-cli.jar config.xml

Note: Due to BeanShell's internal architecture, complete v2.0 scope semantics may not be achievable in all edge cases. The detection mechanism provides a safety net and helps identify potential issues. See Bug #7 documentation for technical details.
