🐛 Debugging Complex Scrapers

Complete guide to debugging WebHarvest configurations for complex websites

Home » Documentation » Debugging Guide

📖 The Problem

"I am developing a scraping tool for a complex javascript website... frequently, I am getting the wrong response. However, it is not easy to spot such instances. Debugging a configuration is really complicated without having a possibility to look at what WebHarvest is actually processing."
— GitHub Issue #16

Common Debugging Challenges

  • ❌ Can't see the actual HTML response being processed
  • ❌ Don't know if HTTP request succeeded or returned error page
  • ❌ Variable values are opaque - hard to inspect
  • ❌ No way to pause and examine state mid-execution
  • ❌ Log is verbose but doesn't show actual data
💡 Good News! WebHarvest has powerful debugging capabilities built-in. This guide shows you 5 debugging patterns you can use RIGHT NOW.
🔍 PATTERN 1: Save Responses to Debug Files

The Workaround That Saves Lives

The simplest and most effective debugging technique: save every response to a file so you can inspect it.

<!-- Fetch page --> <def var="response"> <http url="https://complex-website.com/api/data"> <http-header name="X-API-Key" value="${apiKey}"/> </http> </def> <!-- 🐛 DEBUG: Save response to file --> <file path="debug/response-${sys.timestamp()}.html" action="write"> ${response} </file> <!-- Now process it --> <def var="data"> <xpath expression="//div[@class='result']"> <html-to-xml>${response}</html-to-xml> </xpath> </def>
💡 Pro Tip: Use ${sys.timestamp()} or ${index} to create unique filenames for each request. This prevents overwriting and lets you see the sequence of requests.

Advanced: Conditional Debug Saves

<!-- Only save when something looks wrong --> <def var="statusCode"> <xpath expression="//meta[@name='http-status']/@content"> <html-to-xml>${response}</html-to-xml> </xpath> </def> <if condition="${statusCode != '200'}"> <!-- 🚨 ERROR RESPONSE - Save for inspection! --> <file path="debug/ERROR-${sys.timestamp()}.html" action="write"> <!-- Add metadata header --> <text><!-- DEBUG INFO Status: ${statusCode} URL: https://complex-website.com/api/data Timestamp: ${sys.timestamp()} --> </text> ${response} </file> <log message="ERROR RESPONSE SAVED - Check debug/ERROR-*.html"/> </if>
📊 PATTERN 2: Variable Inspection with Log

See What's Actually in Your Variables

Use <log> to print variable values at key points:

<!-- Extract data --> <def var="productName"> <xpath expression="//h1[@class='product-title']/text()">${page}</xpath> </def> <!-- 🐛 DEBUG: Check what we extracted --> <log message="Product name extracted: '${productName}'"/> <def var="price"> <xpath expression="//span[@class='price']/text()">${page}</xpath> </def> <!-- 🐛 DEBUG: Verify price format --> <log message="Price extracted: '${price}' (length: ${sys.length(price)})"/> <!-- Validate data --> <if condition="${sys.length(productName) == 0}"> <log level="ERROR" message="PROBLEM: Product name is empty!"/> <log message="Page content preview: ${sys.substring(page, 0, 200)}..."/> </if>

Log Levels Available

<log level="DEBUG" message="Detailed trace information"/> <log level="INFO" message="General information (default)"/> <log level="WARN" message="Warning - something unexpected"/> <log level="ERROR" message="Error - operation failed"/>
💡 Configure log4j.properties to control which levels are shown: 
log4j.rootLogger=DEBUG, stdout  # Show DEBUG and above
log4j.rootLogger=INFO, stdout   # Show INFO and above (default)
log4j.rootLogger=WARN, stdout   # Only WARN and ERROR
🔬 PATTERN 3: Step-by-Step Variable Tracking

Track Variable Transformations

When data goes through multiple transformations, save each step:

<!-- STEP 1: Fetch raw HTML --> <def var="rawHtml"> <http url="https://example.com/products"/> </def> <file path="debug/1-raw.html" action="write">${rawHtml}</file> <!-- STEP 2: Convert to XML --> <def var="xmlDoc"> <html-to-xml>${rawHtml}</html-to-xml> </def> <file path="debug/2-xml.xml" action="write">${xmlDoc}</file> <!-- STEP 3: Extract with XPath --> <def var="products"> <xpath expression="//div[@class='product']">${xmlDoc}</xpath> </def> <file path="debug/3-products.txt" action="write">${products}</file> <log message="Extracted ${sys.count(products)} products"/> <!-- STEP 4: Clean/transform --> <def var="cleaned"> <replace regex="\s+" by=" ">${products}</replace> </def> <file path="debug/4-cleaned.txt" action="write">${cleaned}</file>
💡 Result: You get a "paper trail" showing exactly where data gets corrupted or lost. Open files 1, 2, 3, 4 and see which step breaks!
🎯 PATTERN 4: HTTP Request/Response Debugging

Debug Complex HTTP Interactions

For AJAX/API calls, JavaScript-heavy sites, and authentication flows:

<!-- Create debug HTTP wrapper --> <function name="debugHttp"> <param name="url"/> <param name="method" value="GET"/> <param name="label" value="request"/> <!-- Log request --> <log message="[${label}] ${method} ${url}"/> <!-- Make request --> <def var="response"> <http url="${url}" method="${method}"> <body>${requestBody}</body> </http> </def> <!-- Save response --> <file path="debug/http-${label}-${sys.timestamp()}.html" action="write"> <text><!-- REQUEST: ${method} ${url} TIMESTAMP: ${sys.timestamp()} --> </text> ${response} </file> <!-- Check status --> <def var="hasError"> <xpath expression="contains(., 'error') or contains(., '404') or contains(., '500')"> <text>${response}</text> </xpath> </def> <if condition="${hasError}"> <log level="WARN" message="[${label}] Response may contain errors - check debug file"/> </if> <return>${response}</return> </function> <!-- Use it --> <def var="loginResult"> <call name="debugHttp"> <call-param name="url">https://example.com/login</call-param> <call-param name="method">POST</call-param> <call-param name="label">login</call-param> </call> </def>
🧪 PATTERN 5: Try/Catch with Detailed Error Logging

Graceful Error Handling with Full Context

When things go wrong, capture ALL the context:

<try> <body> <!-- Attempt risky operation --> <def var="data"> <xpath expression="//div[@class='data']/text()"> <html-to-xml>${response}</html-to-xml> </xpath> </def> </body> <catch> <!-- 🚨 Something failed - save EVERYTHING --> <log level="ERROR" message="XPath extraction failed!"/> <!-- Save the problematic response --> <file path="debug/FAILED-${sys.timestamp()}.html" action="write"> <text><!-- ERROR CONTEXT Timestamp: ${sys.timestamp()} XPath: //div[@class='data']/text() Response length: ${sys.length(response)} Response preview: --> </text> ${response} </file> <!-- Log error details --> <log level="ERROR" message="Response saved to debug/FAILED-${sys.timestamp()}.html"/> <log level="ERROR" message="Response preview: ${sys.substring(response, 0, 500)}"/> <!-- Set fallback value --> <def var="data">ERROR</def> </catch> </try>

🛠️ Complete Debug Configuration Template

Here's a ready-to-use template with ALL debugging patterns built-in:

<?xml version="1.0" encoding="UTF-8"?> <config> <!-- ================== DEBUG CONFIGURATION ================== --> <def var="DEBUG_MODE">true</def> <def var="DEBUG_DIR">debug/${sys.timestamp()}</def> <!-- Create debug directory --> <if condition="${DEBUG_MODE}"> <log message="🐛 DEBUG MODE ENABLED - Saving responses to ${DEBUG_DIR}/"/> </if> <!-- Debug function wrapper --> <function name="debugSave"> <param name="content"/> <param name="filename"/> <param name="label" value="debug"/> <if condition="${DEBUG_MODE}"> <file path="${DEBUG_DIR}/${filename}" action="write"> ${content} </file> <log message="[${label}] Saved ${DEBUG_DIR}/${filename}"/> </if> <return>${content}</return> </function> <!-- ================== ACTUAL SCRAPING ================== --> <!-- 1. Login --> <def var="loginPage"> <http url="https://complex-website.com/login"/> </def> <call name="debugSave"> <call-param name="content">${loginPage}</call-param> <call-param name="filename">1-login-page.html</call-param> <call-param name="label">LOGIN</call-param> </call> <!-- 2. Submit credentials --> <def var="authResult"> <http url="https://complex-website.com/auth" method="POST"> <http-param name="user" value="test"/> <http-param name="pass" value="secret"/> </http> </def> <call name="debugSave"> <call-param name="content">${authResult}</call-param> <call-param name="filename">2-auth-result.html</call-param> <call-param name="label">AUTH</call-param> </call> <!-- 3. Check if logged in --> <def var="isLoggedIn"> <xpath expression="contains(., 'Welcome')"> <text>${authResult}</text> </xpath> </def> <log message="Login status: ${isLoggedIn}"/> <if condition="${!isLoggedIn}"> <log level="ERROR" message="LOGIN FAILED - Check debug files!"/> <stop/> </if> <!-- 4. Fetch data --> <def var="dataPage"> <http url="https://complex-website.com/data"/> </def> <call name="debugSave"> <call-param name="content">${dataPage}</call-param> <call-param name="filename">3-data-page.html</call-param> <call-param name="label">DATA</call-param> </call> <!-- 5. Extract with error handling --> <try> <body> <def var="results"> <xpath expression="//div[@class='result']"> <html-to-xml>${dataPage}</html-to-xml> </xpath> </def> <log message="Extracted ${sys.count(results)} results"/> </body> <catch> <log level="ERROR" message="XPath extraction failed"/> <file path="${DEBUG_DIR}/ERROR-extraction.html" action="write"> ${dataPage} </file> </catch> </try> </config>
✅ How to Use:
  1. Set DEBUG_MODE to true
  2. Run your scraper
  3. Check debug/[timestamp]/ directory
  4. Open HTML files in browser to see what WebHarvest actually received
  5. Compare expected vs actual responses
  6. Fix XPath expressions based on real data

🔧 Advanced: log4j.properties Configuration

Control logging verbosity at the system level:

# Root logger level (DEBUG shows everything) log4j.rootLogger=DEBUG, stdout # Console appender log4j.appender.stdout=org.apache.log4j.ConsoleAppender log4j.appender.stdout.layout=org.apache.log4j.PatternLayout log4j.appender.stdout.layout.ConversionPattern=%d{HH:mm:ss} %-5p %c{1} - %m%n # Fine-tune specific packages log4j.logger.org.webharvest.plugin=DEBUG log4j.logger.org.webharvest.runtime=INFO log4j.logger.org.apache.http=WARN # File appender for permanent logs log4j.appender.file=org.apache.log4j.FileAppender log4j.appender.file.File=webharvest-debug.log log4j.appender.file.layout=org.apache.log4j.PatternLayout log4j.appender.file.layout.ConversionPattern=%d{yyyy-MM-dd HH:mm:ss} %-5p %c{1} - %m%n

📋 Debugging Checklist

When debugging complex websites, always:
  • ✅ Save responses to files (<file path="debug/...">)
  • ✅ Use unique filenames (${sys.timestamp()})
  • ✅ Log variable values at key points (<log>)
  • ✅ Wrap risky operations in <try>/<catch>
  • ✅ Check HTTP status codes and error messages
  • ✅ Verify authentication succeeded before proceeding
  • ✅ Use ${sys.count(variable)} to check list sizes
  • ✅ Test XPath expressions on ACTUAL responses, not assumptions
