🎓 Complete Tutorial: Form Submit & Pagination

Step-by-step guide for login, form submission, pagination, and detail scraping

Home » Documentation » Form Submit & Pagination Tutorial

📖 What You'll Learn

This tutorial addresses a common request from beginners: "How do I submit forms, handle pagination, and scrape detail pages?"

Workflow Overview:

Login Page → Fill Form → Submit → Results Page 1
↓
For each result: Click link → Scrape detail → Back to results
↓
Click "Next" → Results Page 2 → Repeat
↓
Until no more pages

Real-World Use Case

A user reported spending 8 hours trying to:

  1. ✅ Log into a website (username + password) - Working
  2. ✅ Fill out a form - Working
  3. ❌ Submit the form - STUCK HERE
  4. ❌ Write HTML for each results page - STUCK HERE
  5. ❌ For each name on the page:
    • Go to the hyperlink
    • Save HTML file
    • Go back to results page
✅ Solution: This tutorial provides a complete, working example for all 4 steps above!
📝 STEP 1: Login with Username and Password

First, let's establish a session by logging in:

<!-- STEP 1: Login to website --> <def var="loginPage"> <http url="https://example.com/login"> <http-header name="User-Agent" value="Mozilla/5.0"/> </http> </def> <!-- Extract hidden form fields (CSRF token, etc.) --> <def var="csrfToken"> <xpath expression="//input[@name='csrf_token']/@value"> <html-to-xml>${loginPage}</html-to-xml> </xpath> </def> <!-- POST login credentials --> <def var="loggedIn"> <http url="https://example.com/login" method="POST"> <http-header name="Content-Type" value="application/x-www-form-urlencoded"/> <http-param name="username" value="myuser"/> <http-param name="password" value="mypass"/> <http-param name="csrf_token" value="${csrfToken}"/> </http> </def>
💡 Key Points:
  • method="POST" - Required for form submission
  • http-param - Each form field becomes a parameter
  • Extract CSRF tokens from the login page before submitting
  • Cookies are automatically preserved between requests
📋 STEP 2: Fill Out and Submit a Form

Now that you're logged in, let's fill out a search form and submit it:

<!-- STEP 2: Get the search form page --> <def var="searchFormPage"> <http url="https://example.com/search"/> </def> <!-- Extract form action URL (where to submit) --> <def var="formAction"> <xpath expression="//form[@id='searchForm']/@action"> <html-to-xml>${searchFormPage}</html-to-xml> </xpath> </def> <!-- Submit the form with your data --> <def var="resultsPage1"> <http url="https://example.com${formAction}" method="POST"> <!-- Fill in form fields --> <http-param name="query" value="my search term"/> <http-param name="category" value="products"/> <http-param name="limit" value="50"/> <!-- This simulates clicking the Submit button --> <http-param name="submit" value="Search"/> </http> </def>
✅ THIS IS THE ANSWER TO "HOW TO SUBMIT"!
The <http method="POST"> with <http-param> elements IS the form submission!
You don't need a separate "submit" command - the HTTP POST does it all.
💾 STEP 3: Write HTML for Each Results Page

Save the results page HTML to a file:

<!-- STEP 3: Save results page 1 --> <file path="output/results-page-1.html" action="write"> ${resultsPage1} </file>
💡 Pro Tip: Create the output/ directory before running, or use dynamic filenames with counters.
🔗 STEP 4: Scrape Detail Pages for Each Result

This is the most complex part - for each result link, go to detail page, save it, then "return" to results:

<!-- STEP 4: Extract all result links --> <def var="resultLinks"> <xpath expression="//div[@class='result']//a[@class='detail-link']/@href"> <html-to-xml>${resultsPage1}</html-to-xml> </xpath> </def> <!-- Also extract names for filenames --> <def var="resultNames"> <xpath expression="//div[@class='result']//a[@class='detail-link']/text()"> <html-to-xml>${resultsPage1}</html-to-xml> </xpath> </def> <!-- Loop through each result --> <loop item="link" index="i"> ${resultLinks} <!-- Get corresponding name for this index --> <def var="name"> <xpath expression="//text()[position()=${i}+1]"> <html-to-xml>${resultNames}</html-to-xml> </xpath> </def> <!-- a. Go to the hyperlink for that name --> <def var="detailPage"> <http url="https://example.com${link}"/> </def> <!-- b. Write an HTML file --> <def var="safeName"> <replace regex="[^a-zA-Z0-9]" by="_">${name}</replace> </def> <file path="output/details/${safeName}.html" action="write"> ${detailPage} </file> <!-- c. "Go back" - Not needed! resultsPage1 is still in memory! --> <!-- Just continue the loop --> </loop>
✅ KEY INSIGHT: You don't need to "go back" to the results page!
The ${resultsPage1} variable still contains the HTML. Just keep looping through the links you extracted earlier.
⚠️ Common Mistake: Don't re-fetch the results page inside the loop! Extract ALL links first, then loop through them.
🔄 STEP 5: Handle Pagination (Click "Next")

Now let's handle multiple pages of results:

<!-- STEP 5: Pagination loop --> <def var="currentPage">${resultsPage1}</def> <def var="pageNum">1</def> <while maxloops="100"> <!-- Check if "Next" button exists --> <xpath expression="//a[@class='next-page']/@href"> <html-to-xml>${currentPage}</html-to-xml> </xpath> <body> <!-- Save current page --> <file path="output/results-page-${pageNum}.html" action="write"> ${currentPage} </file> <!-- Extract and process all detail links from current page --> <def var="resultLinks"> <xpath expression="//div[@class='result']//a[@class='detail-link']/@href"> <html-to-xml>${currentPage}</html-to-xml> </xpath> </def> <loop item="link" index="i"> ${resultLinks} <def var="detailPage"> <http url="https://example.com${link}"/> </def> <file path="output/details/page${pageNum}_result${i}.html" action="write"> ${detailPage} </file> </loop> <!-- Get "Next" link --> <def var="nextLink"> <xpath expression="//a[@class='next-page']/@href"> <html-to-xml>${currentPage}</html-to-xml> </xpath> </def> <!-- Click "Next" --> <def var="currentPage"> <http url="https://example.com${nextLink}"/> </def> <!-- Increment page counter --> <def var="pageNum"> <script return="pageNum"> pageNum = parseInt("${pageNum}") + 1; </script> </def> </body> </while>
💡 How This Works:
  1. <while> condition checks if "Next" button exists
  2. If yes, execute the <body>
  3. Process all results on current page
  4. Click "Next" link (fetch new page)
  5. Loop repeats with new currentPage
  6. When no "Next" button found, loop exits

🔧 Troubleshooting Common Issues

Problem 1: "How do I submit the form?"

Answer: <http method="POST"> with <http-param> IS the submit!
There's no separate submit command - the POST request submits the form automatically.

Problem 2: "How do I go back to results page?"

Answer: You don't need to!
Extract all links first into a variable (like ${productLinks}), then loop through them.
The original page HTML is still in memory.

Problem 3: "Pagination doesn't work"

Check these:
  • Is your XPath expression correct for the "Next" button?
  • Does the "Next" link need the base URL prepended?
  • Are you updating currentPage variable correctly?
  • Is maxloops high enough?

Problem 4: "Form submission returns error"

Common causes:
  • Missing CSRF tokens - Extract from form page first
  • Missing cookies - Make sure you logged in first
  • Wrong Content-Type - Use application/x-www-form-urlencoded
  • Missing hidden fields - Extract ALL input fields from form

Problem 5: "Can't extract links correctly"

Debugging tips:
  1. Save the page HTML first: <file path="debug.html" action="write">${currentPage}</file>
  2. Open in browser and inspect the HTML structure
  3. Test XPath in browser console: $x("//your/xpath/here")
  4. Adjust your expression based on actual HTML

🎓 Key Takeaways

✅ Form Submission

<http method="POST"> + <http-param> = Form submit

✅ Detail Pages

Extract ALL links first, then loop - no need to "go back"

✅ Pagination

<while> + XPath check for "Next" + Update current page

✅ Variables Persist

Once you fetch a page into a variable, it stays in memory throughout the loop
