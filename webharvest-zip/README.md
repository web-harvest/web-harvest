# WebHarvest ZIP Module

Optional ZIP archive creation support for the WebHarvest framework.

This module creates ZIP archives in memory and returns the archive as a binary
value. It does **not** extract ZIP files and does **not** write an output file
itself.

## Features

- Create ZIP archives with multiple entries.
- Add text or binary content produced by child processors.
- Preserve directory paths in ZIP entry names.
- Support nested ZIP archives.
- Return the completed archive as a binary `NodeVariable`.

## Optional registration

ZIP is an optional extension, not one of the 44 default Core XML mappings.
Add the `webharvest-zip` module to the runtime and explicitly register its
plugins with `ZipPluginRegistrar.register(CorePluginRegistry.getInstance())`.
The default Core registry does not register `zip` or `zip-entry`.

## Plugins

### `ZipPlugin` (`<zip>`)

Creates an in-memory archive and returns its bytes.

| Attribute | Required | Description |
|-----------|----------|-------------|
| *(none)* | — | The plugin accepts no attributes. |

### `ZipEntryPlugin` (`<zip-entry>`)

Adds one entry to the currently active `<zip>` archive. It must execute inside
an active `<zip>` processor.

| Attribute | Required | Description |
|-----------|----------|-------------|
| `name` | Yes | Entry name inside the archive; use forward slashes for directories |
| `charset` | No | Character set for text content; defaults to the current scraper context charset |

The entry body is evaluated by WebHarvest. Its resulting bytes are written
directly to the ZIP entry, so binary-producing child processors do not need a
separate `type="binary"` attribute.

## Usage examples

### Create an archive

Capture the returned binary value in a variable:

```xml
<config xmlns="http://org.webharvest/schema/2.1/core">
    <def var="archive">
        <zip>
            <zip-entry name="products.xml">
                <http url="https://example.com/products"/>
            </zip-entry>
            <zip-entry name="metadata.txt">
                <template><![CDATA[Generated by Web-Harvest]]></template>
            </zip-entry>
        </zip>
    </def>
</config>
```

### Add several entries

```xml
<config xmlns="http://org.webharvest/schema/2.1/core">
    <def var="archive">
        <zip>
            <zip-entry name="data/products.xml">
                <http url="https://example.com/products"/>
            </zip-entry>
            <zip-entry name="data/users.xml">
                <http url="https://example.com/users"/>
            </zip-entry>
            <zip-entry name="logs/scraping.txt">
                <template><![CDATA[Scraping completed]]></template>
            </zip-entry>
        </zip>
    </def>
</config>
```

### Create a nested archive

A ZIP archive can itself be the body of an entry. The inner archive is completed
before its bytes are written into the outer archive:

```xml
<config xmlns="http://org.webharvest/schema/2.1/core">
    <def var="archive">
        <zip>
            <zip-entry name="before.txt">
                <template><![CDATA[before]]></template>
            </zip-entry>
            <zip-entry name="nested/inner.zip">
                <zip>
                    <zip-entry name="inside.txt">
                        <template><![CDATA[inside]]></template>
                    </zip-entry>
                </zip>
            </zip-entry>
            <zip-entry name="after.txt">
                <template><![CDATA[after]]></template>
            </zip-entry>
        </zip>
    </def>
</config>
```

## Runtime constraints

- The complete archive is held in memory until `<zip>` finishes; keep archive
  sizes within the available heap.
- `<zip-entry>` outside an active `<zip>` context fails explicitly.
- Duplicate entry names are rejected by the ZIP stream implementation.
- This module provides archive creation only; extraction and direct filesystem
  output are not implemented here. Pass the returned binary value to a
  separately supported binary consumer when persistence is required.

## Dependency

```xml
<dependency>
    <groupId>org.webharvest</groupId>
    <artifactId>webharvest-zip</artifactId>
    <version>2.3.1</version>
</dependency>
```

## Testing

Run the optional module together with its Core dependencies:

```bash
mvn -B -ntp -pl webharvest-zip -am verify
```
